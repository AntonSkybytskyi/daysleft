### Stage 1 — AC compliance (blocking) → routed to implement

1. **[T65, BLOCKING, AC-02b]** `spec.md:104-108`, `sad.md:213-215`, and `ux-flows.md:55,128` all
   describe the opening device getting the dashboard with no return to the original — the opposite
   of what T60 ships. Resolved direction: amend the three artifacts (above).
2. **[T66, BLOCKING, AC-01/AC-02]** `CheckEmailContainer.tsx:51-58`'s guard returns silently on
   three preconditions (status ≠ `needs_first_factor`, no `createEmailLinkFlow`, no `email_link`
   factor), leaving `state` at `default`/`resent-confirmation` — both of which render a "link sent"
   message — while no email was sent and nothing polls. `LoginContainer.tsx:53` and
   `SsoCallbackContainer.tsx:118` dropped the old `strategy: "email_link"` send, making the poll the
   *only* sender, so this guard failure is now load-bearing, not cosmetic.
   `CheckEmailContainer.test.tsx:55-65,151-156` pin the silence as correct — the same "test argues
   for the deviation" shape round 4 flagged on the prior T53 attempt.
3. **[T67, BLOCKING, AC-01/AC-02b]** A first-time Traveler's sign-up-branch `ClientMismatch` now
   routes to `verified-elsewhere` (`SsoCallbackContainer.tsx:88-91`), falsely claiming a session
   exists on another device when nothing polls for a sign-up attempt — and
   `MagicLinkInvalidScreen.tsx:40-48` renders no CTA at all in that state, a hard dead end where the
   pre-T60 behavior at least offered a working resend.

### Stage 2 — quality / regressions introduced by this round's own fixes → routed to implement

4. **[T68, MAJOR, AC-03]** `clerk-webhook.ts:70` invalidates unconditionally on every
   `user.created`/`user.updated`, not only on an actual email change — contradicts
   `session.ts:14-19`'s documented purpose and `session.test.ts:117`'s pinned "one Clerk fetch
   total" behavior. `invalidate()` also only deletes by `identityId`
   (`linked-identities-repository.ts:23-25`); the canonical-account side of a stale mapping (the
   direction round 4's finding was actually about) is still permanent.
5. **[T69, MAJOR, AC-02b]** No generation/cancelled/unmount guard on the poll's `.then`/`.catch`
   (`CheckEmailContainer.tsx:63-76`): a resend can have its own new "resent" state clobbered by a
   stale poll settlement, and a settlement after unmount can call `setState`/`setActive`/navigate
   from a screen the user already left. `cancelPollRef` is a single slot with no ownership check.
6. **[T70, MAJOR, tests]** `CheckEmailContainer.test.tsx:122` mocks `status: "expired"`, a value
   the real `SignInStatus` union (`signInCommon.d.ts:7`) cannot produce — real expiry surfaces via
   `firstFactorVerification.status`, which the production code never reads. Separately, the
   load-bearing "don't double-send" change (`LoginContainer.tsx:53`, `SsoCallbackContainer.tsx:118`)
   has zero test coverage — reverting either line to the pre-T60 `strategy: "email_link"` send
   leaves the full suite green.
7. **[T69/T66 overlap, MINOR, AC-02/NFR]** Every `/check-email` mount (refresh, back-nav, StrictMode
   double-invoke) re-runs `startEmailLinkFlow`, silently superseding the outstanding link and
   burning the ≤5/email/hour budget (`spec.md:162-163`). Folded into T69's guard.
8. **[T73, MINOR]** `SsoCallbackContainer.tsx:146` wires a live `onSendNewLink` handle into
   `verified-elsewhere`, inert only because that branch renders no CTA today — a footgun for a
   future edit that adds one back. `CheckEmailContainer.tsx:3-4` imports both `useClerk` and the
   legacy `useSignIn` for a value (`setActive`) the legacy hook already returns, widening the test's
   mock surface for no gain. `clerk-webhook.ts:26`'s `linkedIdentities?` is optional-typed, so the
   AC-03 invalidation safety is opt-in by type rather than enforced.
9. **[T71, MEDIUM, AC-06]** Round-4 finding 2's second half was never addressed: when
   `clerk.signOut()` rejects after the server's 204, `DashboardContainer.tsx:70-77` swallows the
   rejection and redirects, but no client-side cookie/JWT clearing or retry happens — the residual
   live client session can still pass `/dashboard` and `/api/v1/dashboard` until the short-lived
   JWT expires.
10. **[T72, MEDIUM, AC-08]** `MagicLinkInvalidScreen.tsx:27-28`'s new `verifiedElsewhereHeading`/

11. **[process, T64 tracker row]** `tasks/tracker.md`'s prior T64 description said
