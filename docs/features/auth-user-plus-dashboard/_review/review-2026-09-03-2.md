### Stage 1 — AC compliance (blocking) → routed to implement

1. **[T38]** Magic-link completion calls Clerk's OAuth callback API (`handleRedirectCallback`)
   instead of `handleEmailLinkVerification` — `SsoCallbackContainer.tsx:21-30,38`. The SCR-04
   invalid-link branch only fires against a fabricated Clerk error shape; against real Clerk an
   expired/used link likely never completes verification at all. AC-01, AC-02, AC-02b.
2. **[T39]** `resolveLoginReturnTo` has a path-traversal bypass: `return_to=/..//evil.example/x`
   resolves to `//evil.example/x`, which a browser treats as protocol-relative → off-origin
   redirect. Confirmed by executing the real exported function. `return-to.ts:13-17`. The
   feature's stated #1 quality goal, still failing. AC-04.
3. **[T40]** Webhook dedupe cache is consulted *before* signature verification —
   `clerk-webhook.ts:38-45` — so an unauthenticated POST with a replayed `svix-id` returns a
   cached user's id/email with no signature check. Flagged independently by both reviewers.
4. **[T41]** Account-linking never persists the second Clerk identity, so `findById` misses on
   every subsequent request, re-hitting Clerk's API and permanently showing the "linked" banner
   — `session.ts:20,29-43`, `account-linking.ts:20-25`. AC-03.
5. **[T42]** AC-08 i18n regressed on new code: `MagicLinkInvalidScreen` renders with no `strings`
   prop (dead catalog keys), `dashboard.errorFetchFailed` isn't in the catalog at all —
   `SsoCallbackContainer.tsx:54`, `DashboardScreen.tsx:21`.
6. **[T43]** Contract drift: the 200 dashboard body now carries `linked` and the webhook's
   ignored-event body is `{ignored,type}`, neither reflected in `openapi.yaml`'s
   `additionalProperties:false` schemas — `get-dashboard.ts:36-43`, `clerk-webhook.ts:56`.
7. **[T46]** `getSessionUser`'s email-conflict branch collapses to `auth.session_invalid`
   instead of a distinct code, so the Traveler redirect-loops to `/login` while their Clerk
   session is still valid — `session.ts:39-41`. AC-03b.
8. **[T47]** e2e scenario 3 cannot pass even with `E2E_HAS_LIVE_CLERK` set — no testing-token
   harness or link-retrieval step exists to complete the magic link —
   `e2e/auth-dashboard.spec.ts:72-79`. AC-01, AC-07 e2e coverage claim doesn't hold.
9. **[T48]** `CheckEmailContainer`'s resend drops `return_to`, has no sign-up fallback (breaks
   for the first-time-email path `LoginContainer` just added), and mislabels every failure as
   rate-limited — `CheckEmailContainer.tsx:22-30`. AC-02b, AC-04.
10. **[T49]** SCR-04's "send new link" just navigates to `/login` — never resends, never reaches
    2 of its 3 declared states — `SsoCallbackContainer.tsx:54`. AC-02.
