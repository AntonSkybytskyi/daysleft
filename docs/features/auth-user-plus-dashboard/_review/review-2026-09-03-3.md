### Stage 1 — AC compliance (blocking) → routed to implement

1. **[T53]** AC-02b's outcome isn't delivered on either Clerk branch — a magic link opened on a
   different device never establishes a session there; `onVerifiedOnOtherDevice` navigates to
   `/dashboard` with no session (middleware bounces it back to `/login`), and `ClientMismatch`
   falls into the generic AC-01b failure screen. Both tests assert the broken behavior as if it
   were the AC — `SsoCallbackContainer.tsx:39,60,66`. AC-02b.
2. **[T54]** Logout revokes server-side but never calls Clerk's client `signOut()`; the browser
   keeps its session JWT and the dashboard stays reachable until it naturally expires (Clerk's
   default ~60s) — `DashboardContainer.tsx:54-67`. AC-06.
3. **[T55]** The "linked" resolution is a process-local `Map` (`defaultLinkedIdentities`),
   contradicting `sad.md` §7 ("stateless per-instance... session state lives in Clerk, not
   in-process") and the contract's guarantee the banner shows once — on any other instance the
   banner and the Clerk API round-trip repeat indefinitely; the map also never evicts —
   `session.ts:19-22,35-43,63-65`. AC-03.
4. **[T56]** Contract drift: the dashboard 401 emits `auth.email_conflict`, undocumented in
   `openapi.yaml`'s enumerated codes/examples — `get-dashboard.ts:28-37` vs
   `openapi.yaml:125-149`. AC-03b.

### Stage 2 — quality / security → routed to implement

5. **[T56]** `screens.md` manifest drift, the mirror of T51: SCR-01 ships `error-email-conflict`
   and SCR-02 ships `error-sign-in-failed`, neither declared in the manifest — `screens.md:27-31`,
   `screens.md:82-86`.
6. **[T56]** The dashboard 200 example omits the now-`required` `linked` field —
   `openapi.yaml:122-124` vs `:240`.
7. **[T56]** `ClerkWebhookEvent.type`'s enum (`user.created`/`user.updated` only) contradicts the
   ignored-event example (`session.created`) and the handler, which accepts any event type by
   design — `openapi.yaml:281` vs `:78`.
8. **[T57]** SCR-04's resend has no sign-up fallback (unlike `LoginContainer`/
   `CheckEmailContainer`) and silently swallows non-429 failures with nowhere to show them —
   `SsoCallbackContainer.tsx:86,93`.
9. **[T58]** A failed logout renders the dashboard-fetch-failed copy ("Couldn't load your
   dashboard") instead of a logout-specific message, misdescribing the failure —
   `DashboardContainer.tsx:59-61`.
10. **[T59]** The `migrate-down` test re-implements the journal-cleanup SQL inline instead of

    green — `migrate-down.test.ts:72` vs `scripts/migrate-down.ts:55`.
