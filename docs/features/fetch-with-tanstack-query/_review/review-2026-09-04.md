## Findings

### F1 — `enabled` gate makes AC-03's redirect unreachable and can replace rendered data with a permanent spinner (Medium-High, stage 1) — **Fix now**

`src/modules/dashboard/ui/DashboardContainer.tsx:31` gates the query on `isLoaded && Boolean(user) && !sessionCleared`; `:53` maps `!enabled` to the `"loading"` state, which renders the standalone spinner (`src/modules/dashboard/ui/DashboardScreen.tsx:43`). AC-03's redirect only fires from a fetch returning the invalid-session signal (`src/modules/dashboard/app/dashboard-query.ts:36-39` → `DashboardContainer.tsx:39-43`). So if Clerk's `user` goes null while the container stays mounted (session revoked from another device, token-refresh failure, sign-out in another tab), no fetch is issued, no redirect fires, and an already-rendered dashboard flips to an indefinite spinner — the empty-screen outcome US-04 exists to prevent, and a regression against the pre-migration container (`git show 6ea354d:src/modules/dashboard/ui/DashboardContainer.tsx`), which fetched unconditionally on mount.

`src/middleware.ts:6` narrows reachability to navigations but does not close the "session dies while the tab stays mounted" window. Untested: `DashboardContainer.test.tsx:12,49` hardcode `{ user: { id: "u1" }, isLoaded: true }`; there is no `{ user: null, isLoaded: true }` case in the suite.

Touches: US-04, AC-03, AC-01.

### F2 — the retry label bypasses the i18n catalog (Medium, stage 1) — **Not an issue**

`src/modules/dashboard/ui/DashboardScreen.tsx:26` hardcodes `retry: "Try again"` in `defaultStrings`. sad.md §8 (Internationalisation) names this string as the example: "New UI strings (the retry control's label, etc.) added to the existing catalog | `src/lib/i18n/en.json`". The other six dashboard strings are in the catalog; `dashboard.retry` is not, and `src/app/dashboard/strings.ts:5-12` neither lists nor maps it — so the AC-02 retry button renders English regardless of `Accept-Language` while every other string on the same screen localizes. `src/lib/i18n/catalog-coverage.test.ts` only asserts that catalog keys are referenced (no dead keys), so it structurally cannot catch a missing key.

Touches: AC-02, sad.md §8. Dismissed by the user without a technical rebuttal of the citation — the sad.md §8 gap stands on the record, but the user judged it non-blocking for this pass.

### F3 — module-scope `QueryClient` in a component that server-renders (Medium, stage 2) — **Fix now**

`src/app/providers.tsx:5` constructs `new QueryClient()` at module scope. `Providers` is a client component but still renders on the server (`src/app/layout.tsx:20-22` wraps `children`; `src/app/dashboard/page.tsx` is a server component), so one instance is shared across every concurrent server render in the process. That contradicts spec §6.1's "the cache is client-side, per-device, and per-Traveler-identity … it never mixes data across Travelers", and ADR-0002's per-device framing.

No live leak today — React Query does not fetch during SSR without an explicit `prefetchQuery`/`HydrationBoundary` — but the cached payload is classified confidential (it carries the Traveler's email), and this feature is explicitly the app-wide template other modules copy (spec Goal 3). Shipping the anti-pattern as the reference implementation is the expensive part. Fix is the standard per-render client (`useState(() => new QueryClient())`); `src/app/providers.test.tsx:20-27` renders `Providers` directly and needs no change.

Touches: AC-05, QG-3, spec §6.1.

### F4 — AC-04's durability is mount-scoped, and its test drives a path production cannot reach (Low, stage 1) — **Defer**

`DashboardContainer.tsx:66` holds the shown-confirmation in `useState(false)`, scoped to the component instance. AC-04 requires the confirmation to remain visible "for the rest of the sign-in session", and AC-01 counts a re-mount as a same-session revisit — so if the cache ever holds `linked:false` after the banner was shown, a re-mount drops it. Related: `DashboardContainer.test.tsx:420` forces the later fetch with `client.refetchQueries(...)` while its comment (`:417-419`) claims to model the AC-02 retry path; no production path can produce a second fetch once data is cached (`dashboard-query.ts:56-60`: `staleTime`/`gcTime` `Infinity`, `refetchOnWindowFocus`/`refetchOnReconnect`/`retry` false), and the retry button renders only in the `error` state, which requires no cached data.

Not a live bug: the invariant holds today by a coincidence of the refetch config rather than by the state's scope. It breaks silently, with no test to catch it, if anyone relaxes `staleTime` or adds a refetch trigger.

### F5 — T7's "coverage already satisfied" closure overclaims for DashboardScreen (Low, stage 2) — **Defer**

`docs/features/fetch-with-tanstack-query/tasks/tracker.md` marks T7 done as "satisfied by T3–T6's RED tests", closed by 8292954. `src/modules/dashboard/ui/DashboardScreen.test.tsx` gained only `onRetry={vi.fn()}` prop plumbing: there is no screen-level test that the `error` state renders the "Try again" button, that clicking it calls `onRetry`, or that `isRetrying` renders the button's spinner — all three declared in screens.md SCR-01's `error` row, on the declared target-surface artifact. Separately, the test plan's AC-06 row requires the loading indicator to render "both on first mount and after triggering the AC-02 retry"; the first-mount half is covered (`DashboardContainer.test.tsx:306-322`), the retry half asserts only that the button is disabled (`:392`), never that a spinner is present. Missing assertions, not missing behavior.

### F6 — the container test harness masks the production provider's defaults (nit, stage 2) — **Not an issue**

`DashboardContainer.test.tsx:29` builds every client with `defaultOptions: { queries: { retry: false } }` while production uses a bare `new QueryClient()` (`src/app/providers.tsx:5`, TanStack default `retry: 3`). AC-02's "no automatic retry" is genuinely satisfied by `dashboard-query.ts:60` and asserted in `dashboard-query.test.ts:30-32`, so a provider-level regression would be invisible to the container suite that reads as if it proved AC-02 end-to-end. AC-02 itself is covered elsewhere — dismissed as a nit, no action.
