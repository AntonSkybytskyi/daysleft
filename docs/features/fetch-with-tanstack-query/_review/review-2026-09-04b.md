## Findings and resolutions

### F1-a — the new AC-03 test mounts with a null user instead of transitioning to one (stage 1) — **Not an issue**

`DashboardContainer.test.tsx`'s "redirects to sign-in ... when Clerk's user goes null on an already-mounted container" test sets `useUserMock.mockReturnValue({ user: null, ... })` before `renderDashboard()`, with no `rerender`. It proves "mount while signed out," not the mid-session transition F1 named. Production code is verified correct regardless (`sessionLost` recomputes on any rerender; effect deps `[sessionLost, router]` fire once). User dismissed as not-an-issue — no test change made.

### F1-b — the fix's zero-fetch redirect doesn't match AC-03's fetch-driven `When` clause (stage 1) — **Fixed**

AC-03 as written required an actual fetch whose response carries the invalid-session signal; the F1 fix redirects on a null `user` with no fetch at all, which is the right behavior for US-04 but wasn't covered by AC-03's literal wording. Fixed by widening AC-03's `When` clause (`spec.md`) to add the no-fetch trigger explicitly, and adding the corresponding `alt` branch + mapping-table row to `sad.md` §6 Flow 1.

### F1-c — the new redirect hand-builds `return_to` from `window.location`, bypassing `resolveReturnTo` (stage 2) — **Fixed**

Every other `return_to` producer in the repo (`middleware.ts`, the server's `resolveLoginUrl`) goes through `resolveReturnTo`, which rejects `//host` / `/\` protocol-relative paths. Not a live vuln (the container only renders under `/dashboard(.*)`), but a convention gap on the reference implementation. Fixed: `DashboardContainer.tsx` now imports `resolveReturnTo` + `DASHBOARD_PATH` and sanitizes the path before building the login URL.

### F3-nit — test name overclaimed "server-render safety" and captured the client during render (stage 2, nit) — **Fixed**

`providers.test.tsx`'s new test only proves per-instance clients across two client-root renders, not concurrent-SSR sharing; it also called `onClient()` synchronously in the render body (StrictMode double-fire risk). Fixed: renamed the test, moved the capture into a `useEffect`.
